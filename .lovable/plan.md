# เชื่อมเครื่องมือภายนอกผ่าน API และ MCP + ตรวจสอบความจำของ Agent

## สถานะจริงที่ตรวจพบตอนนี้

**เครื่องมือผ่าน API — มีแล้วและทำงานจริง**
Agent เรียก API ภายนอกของผู้ใช้ได้แล้ว (กำหนด URL, วิธีเรียก, พารามิเตอร์, กุญแจ/โทเคน) ทั้งในหน้าแชท, API สาธารณะ และ Widget มีการกันเรียกเครือข่ายภายใน จำกัดเวลา 10 วินาที และตัดผลลัพธ์ที่ยาวเกิน สูงสุด 10 เครื่องมือต่อ Agent
ที่ยังขาด: ต้องกรอกทีละช่องเอง ไม่มีการนำเข้าจากเอกสาร API (OpenAPI/Swagger) และตั้งค่า header เพิ่มเองไม่ได้

**เครื่องมือผ่าน MCP — ยังไม่มีเลย** ไม่พบส่วนใดในระบบที่รองรับ MCP

**ความจำ — มีจริง แต่ฝั่ง API มีจุดบกพร่อง**
- หน้าแชทในเว็บ: จำได้จริง — โหลดข้อความเก่าทั้งหมดจากฐานข้อมูล และเมื่อบทสนทนายาวเกิน 20 ข้อความจะสรุปความเก่าเก็บไว้ แล้วส่งสรุปนั้นไปพร้อมทุกคำถามใหม่ (ปิดได้ด้วยสวิตช์ "ความจำ" ของ Agent)
- ผ่าน API ด้วย `session_id`: จำได้ แต่**ดึงข้อความเก่าที่สุด 40 ข้อความ** ไม่ใช่ล่าสุด ดังนั้นเมื่อคุยเกิน 40 ข้อความ Agent จะจำแต่ตอนต้นและ**ลืมสิ่งที่เพิ่งคุยไป** และไม่มีการสรุปความเก่าเหมือนหน้าเว็บ

## สิ่งที่จะทำ

### 1. รองรับ MCP (ใหม่)

- เพิ่มหัวข้อ **"เซิร์ฟเวอร์ MCP"** ในแท็บ Enterprise ของหน้า Agent: ใส่ชื่อ, ที่อยู่เซิร์ฟเวอร์ (https เท่านั้น), วิธียืนยันตัวตนแบบโทเคน (ไม่มี / Bearer / header ที่กำหนดเอง)
- ปุ่ม **"ทดสอบและดึงรายการเครื่องมือ"** — ต่อเข้าเซิร์ฟเวอร์จริง แสดงรายชื่อเครื่องมือที่ได้พร้อมคำอธิบาย และให้เลือกว่าจะอนุญาตให้ Agent ใช้ตัวไหนบ้าง
- ขณะสนทนา Agent จะเห็นเครื่องมือจาก MCP ปนกับเครื่องมืออื่น เรียกใช้ได้เอง และผลลัพธ์จะขึ้นในหน้า Monitor เหมือนเครื่องมือปกติ
- ความปลอดภัยชุดเดียวกับเครื่องมือ API: บล็อกที่อยู่ภายใน, จำกัดเวลาต่อครั้ง, จำกัดขนาดผลลัพธ์, สูงสุด 5 เซิร์ฟเวอร์และ 30 เครื่องมือ MCP ต่อ Agent, โทเคนไม่ถูกส่งกลับมาที่หน้าเว็บ
- รอบนี้รองรับการยืนยันตัวตนแบบโทเคน (ครอบคลุมเซิร์ฟเวอร์ MCP ส่วนใหญ่) ยังไม่รองรับแบบ OAuth ที่ต้องกดอนุญาตในหน้าเว็บของผู้ให้บริการ

### 2. เสริมเครื่องมือแบบ API เดิม

- นำเข้าเครื่องมือจากเอกสาร API (OpenAPI/Swagger) ได้ในคลิกเดียว เลือก endpoint ที่ต้องการ แล้วระบบเติมพารามิเตอร์ให้อัตโนมัติ
- เพิ่ม header เองได้หลายรายการ (เช่น เวอร์ชัน API)

### 3. แก้และยืนยันเรื่องความจำ

- แก้ให้ฝั่ง API ดึง **ข้อความล่าสุด** และเพิ่มการสรุปความเก่าแบบเดียวกับหน้าเว็บ เพื่อให้บทสนทนายาวยังจำบริบทได้
- แสดงสถานะความจำในหน้า Agent: จำนวนข้อความที่จำอยู่ และสรุปความที่ระบบเก็บไว้ พร้อมปุ่มล้างความจำ
- **ทดสอบจริงแบบ end-to-end**: บอกชื่อ/ความชอบในข้อความแรก แล้วถามย้อนในข้อความถัดไป ทั้งในหน้าแชท และผ่าน API ด้วย session เดียวกัน รวมถึงทดสอบบทสนทนายาวเกิน 40 ข้อความว่ายังจำเรื่องล่าสุดได้ และทดสอบว่าปิดสวิตช์ความจำแล้วลืมจริง

## รายละเอียดทางเทคนิค

- ตารางใหม่ `agent_mcp_servers` (agent_id, user_id, name, url, transport, auth_type, auth_header_name, auth_secret, enabled, allowed_tools text[], cached_tools jsonb, last_synced_at, last_status) + RLS เจ้าของเท่านั้น + GRANT; เพิกถอนสิทธิ์อ่าน `auth_secret` จากฝั่งเบราว์เซอร์เหมือน `agent_custom_tools`
- `supabase/functions/_shared/mcp-client.ts`: JSON-RPC over Streamable HTTP — `initialize` → `tools/list` → `tools/call`, รองรับผลลัพธ์แบบ SSE, ใช้ `assertSafeUrl` จาก `_shared/url-safety.ts`, timeout 15s, ตัดผลลัพธ์ที่ 8KB
- `_shared/mcp-tools.ts`: แปลง MCP tool → OpenAI function schema, ตั้งชื่อแบบ `mcp_<server>_<tool>` กันชนกัน และคืน executor เข้า `extraExec` ของ `runToolLoop` (จุดต่อเดียวกับ custom tools) ใน `chat/index.ts` และ `agent-api/index.ts`
- Edge function ใหม่ `mcp-connect` (list/test/sync เครื่องมือ ตรวจสิทธิ์เจ้าของด้วย JWT) และ `import-openapi` สำหรับข้อ 2
- แก้ `agent-api/index.ts`: ดึงประวัติด้วย `order(created_at, desc).limit(40)` แล้วกลับลำดับ, เพิ่มคอลัมน์สรุปเดิม (`memory_summary`) เข้า flow และเรียก `maybeSummarize` ที่ย้ายไป `_shared/memory.ts` ใช้ร่วมกับ `chat/index.ts`
- ฝั่งหน้าเว็บ: `useMcpServers.ts`, `McpServersSection.tsx`, `MemoryCard.tsx`, i18n ไทย/อังกฤษ, และอัปเดต `/docs/api` เรื่อง session memory + MCP
